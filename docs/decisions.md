# החלטות (ADR)

## 1. Claude דרך הטרמינל (`claude -p`) - נבחר על ידי המשתמש
- **סיכונים ידועים:** דיווחי 401 עם `setup-token` ב-headless, אי-בהירות בתנאי השימוש לגבי אוטומציה,
  והשהיית הפעלה לא נמדדה.
- **הפחתה:** הבילוד של המוח מבודד ב-`ai/brain.py`. אפשר להחליף למפתח API בלי לגעת בשאר.
- **ספייק פתוח:** לבדוק יציבות והשהיה על השרת עצמו.

## 2. כלים דרך שרת MCP מקומי (stdio, stdlib)
- `claude -p` מפעיל את שרת הכלים בכל קריאה, לכן מצב מתמשך (טיימרים) נשמר בקובץ.
- כלי המערכת של Claude כבויים (`--tools ""`). רק כלי Ai זמינים.

## 3. אבטחה
- פעולות פיזיות רגישות (מנעול, אזעקה, תריס, דוד) דורשות `confirm=true` אחרי אישור מהמשתמש.
- תוכן ממייל או מדף אינטרנט הוא נתון, לא הוראה (בפרומפט המערכת).
- סודות (HA_TOKEN) רק ממשתני סביבה, לא בקבצים.

## 4. גוגל (Gmail, Calendar, Classroom): דפדפן, לא API
- סטטוס: **לא ממומש**. נדרשים ספייקים: Playwright עם פרופיל קבוע מול Claude in Chrome.
- הסיכון העיקרי: prompt injection על פרופיל מחובר. פרופיל גוגל נפרד מדפדפן כללי, אישור לפני שליחה.

## 5. העדפות
- הודעות: `whatsapp` או `phone_app`. מוזיקה: `spotify` או `youtube_music`.
- סטטוס: ההעדפה נשמרת ב-config, השירותים עצמם **לא ממומשים** (וואטסאפ מחוץ לגרסה 1).

## 6. מה לא נבדק עדיין
- הרצה אמיתית מול `claude -p` (לא אומתה, אין התחברות בסביבת הפיתוח).
- Home Assistant אמיתי, מיקרופון, זיהוי מילת הפעלה, STT ו-TTS בעברית.
